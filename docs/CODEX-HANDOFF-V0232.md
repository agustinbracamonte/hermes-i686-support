## Environment and fundamental architecture trap
- Target is Debian 11 i386/32-bit **userspace** on a host where `uname -m` and `platform.machine()` can report `x86_64`.
- The user's CPython process reports `struct.calcsize("P") == 4` while some `sysconfig` platform fields report x86_64. Therefore: **kernel architecture is not process/userspace ABI**.
- The expected native target is `linux-i686` (glibc), `ELFCLASS32` and `EM_386`. Verify shared libraries and executable dependencies, not filenames alone.
- Low-resource original hardware: about 2 GiB RAM, about 1 GiB swap, slow serial builds; build machine may differ from runtime test machine.
- User has separate, live Hermes 0.20 production; all development is off-production.

A partial local patch targeting process ABI and ELF32 reportedly passed **27 tests, 2 skipped**, but full bootstrap and package-manager sync have **not** been verified.

- New runtime pins: Python **3.14.9**, Node **26.12.1**, uv **0.13.5**. An official uv i686 artifact was reportedly verified. Earlier Python 3.14.7 and Node 26.7.0 staging assets do not satisfy new pins. Rust/Cargo 1.97.1 i686 already exists privately and may be used in the target staging but must not be published here.
- Of **102 Linux dependencies** for the `all` extra: **44** have existing exact-lock wheel matches; **48** have compatible locked wheels that must still be retrieved; **10** have no locked i686-compatible wheel and may require local builds. Two possible candidates, `cffi 2.1.1` and `psutil 7.2.2`, passed isolated checks but have not passed the new lock/venv integration. Thus **8–10** builds remain; do not claim eight confirmed.
- Lock changed materially from v0.22: `uv.lock` records 326 -> 355; `all` extra selection changed. Do not reuse old wheelhouses without exact version/tag/hash/ABI verification.
