# FFmpeg 9.0.1 i686 validation

Hermes v0.23.2 currently pins the BtbN GPL build named `ffmpeg-n9.0.1-11-ge47273f4d9-linux64-gpl-9.0.tar.xz`; its published checksum is for x64 only. The suffix identifies FFmpeg commit `e47273f4d9227152dcbf543cebaf9e2430ddbcc4`, 11 commits beyond the signed upstream `n9.0.1` tag. The suffix commit is not signed. The new i686 build recipe defaults to the signed `n9.0.1` tag to keep the source pin within reviewed release provenance. This source is not byte-for-byte or commit-identical to the existing x64 build. If matching the BtbN source lineage becomes a requirement, review those 11 post-tag commits before changing the i686 source pin.

The hosted run below verified ephemeral i686 FFmpeg/ffprobe executables and retained their hashes, but no binary artifact is retained and there is still no PM lock row or approved target package. Do not reuse the x64 digest. Build from the selected full upstream commit in an isolated Debian 11 i386 environment, serially, and retain the source commit/tree, configure arguments, compiler and dependency package versions, output hashes, and linker closure. The proposed feature profile enables GPL, libx264, libopus, libmp3lame, libxcb/X11 capture, native AAC, and `lavfi`; it must not enable `--enable-nonfree`. The resulting build has GPL redistribution obligations that require review before packaging.

## Source-build recipe

`scripts/build-v0232-ffmpeg-i686.sh` implements a serial, resumable build from the exact upstream tag object `501bb49457b9dfb25d6a208832e0a6e6cd53108d`, commit `bf1b838f2ab88b4f8fd83443325c782ea0e0f7fa`, and tree `68fad6870d0f112fcf4e385d798bf268b2b938b0`. It fetches only that tag, compares all three identifiers, rejects a dirty or mismatched source checkout, and never installs operating-system packages. The script does not invoke GPG; it anchors source selection to the fixed tag-object digest previously checked against the signed tag. Its output directory is rooted under `HERMES_I686_BUILD_ROOT`; the source checkout, configure, compile, install, smoke-check, static-verifier, build-info, and local archive steps each have a fingerprinted checkpoint. It rejects QEMU-marked environments before running the built executables. `make` is fixed at `-j1` for a constrained 2 GiB target.

The build requires an already prepared Debian 11 i386 environment and installed build dependencies: `build-essential`, `ca-certificates`, `git`, `pkg-config`, `nasm`, `libx264-dev`, `libopus-dev`, `libmp3lame-dev`, `libxcb1-dev`, `libxcb-shm0-dev`, `libxcb-shape0-dev`, and `libxcb-xfixes0-dev`. The script checks the `x264`, `opus`, and XCB pkg-config modules and records exact Debian package and module versions in `BUILD-INFO.txt`. FFmpeg 9.0.1 checks libmp3lame directly using its header and linker symbol, so the recipe does not require a `libmp3lame.pc` file. A read-only fetch of `configure` at the pinned commit had SHA-256 `5b281b249ad5ad859030b4da0a24ec105b5abff7b3d87a65b302df8bf5fd9833`; that exact file lists the selected codec and XCB configure switches and maps the XCB subfeatures to the `xcb-shm`, `xcb-shape`, and `xcb-xfixes` pkg-config modules. The script does not yet pin Debian packages to a snapshot or prove bit-for-bit reproducibility across hosts; dependency snapshot selection remains an open step. The configure profile enables GPL, x264, Opus, MP3, and XCB capture, disables FFplay/docs/debug, and rejects a nonfree build.

The recipe creates a local deterministic-metadata `.tar.xz` from its install prefix and writes the artifact digest outside the archive. It does not publish the archive. On 2026-11-19, `--prepare-only` fetched the exact tag into a disposable x86_64 development build root and verified tag object `501bb49457b9dfb25d6a208832e0a6e6cd53108d`, commit `bf1b838f2ab88b4f8fd83443325c782ea0e0f7fa`, tree `68fad6870d0f112fcf4e385d798bf268b2b938b0`, and a clean checkout. The source checkout occupied 135 MiB; `configure` SHA-256 matched the independently fetched value above. This is source-preparation evidence only, not an i686 build. No compiled artifact hash, PM row, lock integration, runtime library closure, or native B10 result is established. Run the separate `--runtime` verifier in isolated Debian 11 i386 staging after building; it needs Xvfb for the synthetic X11 capture check. Review GPL notices and redistribution terms before packaging the result.

## Artifact verification

The helper `scripts/verify-v0232-ffmpeg-i686.sh` has two explicit modes. Static mode never runs the binaries:

```bash
scripts/verify-v0232-ffmpeg-i686.sh --static-only \
  /path/to/ffmpeg /path/to/ffprobe /tmp/ffmpeg-static-report
```

It checks both files are executable little-endian ELF32/EM_386 images and records their SHA-256, `DT_NEEDED` libraries, and maximum GLIBC symbol versions. It rejects a requirement newer than Bullseye's GLIBC 2.31. A claimed source commit is recorded only when provided in `FFMPEG_SOURCE_COMMIT`; the verifier cannot prove source provenance from an executable.

Runtime mode must run inside a native Debian 11 i386 userspace. The helper checks its own process ABI, rejects QEMU-marked environments, and inspects live FFmpeg and FFprobe PIDs to confirm `/proc/PID/exe` resolves to each supplied ELF32 binary. It checks `getconf LONG_BIT`, `dpkg --print-architecture`, library resolution and ELF32 library dependencies. It captures FFmpeg's version banner from either output stream and requires an exact match to the selected source pin: `n9.0.1-11-ge47273f4d9` for the BtbN-lineage commit or `n9.0.1` for the signed tag. Prefix matches and other suffix commits are rejected. It then checks required build options, encodes and decodes synthetic H.264, AAC, Opus and MP3 samples, captures a frame from an isolated Xvfb display through `x11grab`, and records peak RSS for the H.264 encode.

Runtime mode invokes the supplied FFmpeg and FFprobe executables and uses `ldd`; use it only for binaries built from the reviewed source in an isolated staging environment. Static mode never invokes the supplied executables.

```bash
FFMPEG_SOURCE_COMMIT=e47273f4d9227152dcbf543cebaf9e2430ddbcc4 \
  scripts/verify-v0232-ffmpeg-i686.sh --runtime \
  /path/to/ffmpeg /path/to/ffprobe /tmp/ffmpeg-i686-report
```

The runtime report is safe to retain as staging evidence, but static fixture results are not execution evidence. A PM lock row can be added only after the selected source is built, the target artifact and its full PM archive are hashed, the runtime/dependency checks pass, and the actual staging PM install verifies that digest. Do not upload binaries or private staging data to this public repository.

## Disposable hosted i686 build check

The hosted build initially exposed an FFmpeg out-of-tree configure behavior: it creates `BUILD/src` as a symlink to the separately pinned, read-only `SOURCE` tree. The build safety check now permits only that explicitly supplied source root as an external symlink target; every other symlink target must remain under its owning build directory. The local regression fixture verifies both the source exception and rejection of an unrelated external target. This policy change is limited to the FFmpeg builder.

The `v0232-ffmpeg-i686.yml` workflow is scoped to pushes on the review branch `codex/v0232-ffmpeg-ci`, uses the standard `ubuntu-24.04` GitHub-hosted runner, and has no token permissions, secrets, release, cache, or artifact upload. [GitHub documents standard hosted runners in public repositories as free](https://docs.github.com/en/actions/concepts/billing-and-usage); this workflow does not use a larger runner or retain binary artifacts. The job creates a Debian 11 i386 chroot from snapshot `20260912T092708Z`, installs only the build and synthetic-runtime dependencies there, mounts its exact source commit read-only, then runs the pinned serial FFmpeg recipe and the synthetic native verifier without QEMU. The temporary chroot, local package archive, and executable outputs are removed when the job ends; only package-version text, runtime/static verification reports, and SHA-256 values are left in the Actions logs/summary.

This hosted build checks an ELF32 runtime under the runner's x86_64 kernel; it does not establish B10 performance, fit within the B10 memory budget, PM lock integration, package redistribution approval, or readiness to cut over.
